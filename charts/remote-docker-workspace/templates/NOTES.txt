{{ include "remote-docker-workspace.fullname" . }} is installed.

Enrol a device with a single-use token. Mint one for an account:

    kubectl exec -n {{ .Release.Namespace }} {{ include "remote-docker-workspace.fullname" . }}-0 -- \
      remote-dockerd token create --account alice{{ if not (include "remote-docker-workspace.publicURL" .) }} --url <address devices reach>{{ end }}

It prints a `docker remote create ... --token ...` line: run that on the
device, which enrols its own key. The key is stored on the state volume, not
in the authorizedKeys Secret.
{{- if gt (int .Values.replicas) 1 }}

There are {{ .Values.replicas }} replicas, each a workspace of its own. A token enrols a
key only on the replica that minted it; a key in the authorizedKeys Secret is
enrolled on every one.
{{- if not .Values.publicURL }}
Its invite names that pod, which only clients inside the cluster reach:

    ssh://<pod>.{{ include "remote-docker-workspace.headlessName" . }}.{{ .Release.Namespace }}.svc:2222

From outside, set publicURL, or enrol with the Secret.
{{- end }}
{{- end }}
{{- if .Values.admins }}

Admins ({{ join ", " .Values.admins }}) can then mint tokens and remove
accounts from their own machines: `docker remote token create --account bob`.
{{- end }}

{{- if not .Values.authorizedKeys }}
{{- if not .Values.existingSecret }}

Or enrol a key by file, one per account:

    helm upgrade {{ .Release.Name }} <chart> --reuse-values \
      --set-file authorizedKeys.alice=$HOME/.ssh/id_ed25519.pub

The name you use ("alice" above) is the account, and what clients pass as
--user.
{{- end }}
{{- end }}

{{- if .Values.securityContext.privileged }}

The pod is privileged, because dockerd sets up its own bridge and iptables
rules and mounts NFS in its own namespace. If your cluster enforces Pod
Security and this namespace is not labelled for it, the pod will not be
admitted and the StatefulSet will report it:

    kubectl label namespace {{ .Release.Namespace }} \
      pod-security.kubernetes.io/enforce=privileged
{{- end }}

{{- if .Values.ingress.enabled }}

Reach it from a laptop with no Docker installed, once its token is redeemed:

    docker run --rm -v ${PWD}:/w alpine:3 ls /w

The directory is served from the machine you typed that on, over the same
connection.
{{- if and (gt (int .Values.replicas) 1) (not (hasKey .Values.ingress.annotations "nginx.ingress.kubernetes.io/upstream-hash-by")) }}

WARNING: {{ .Values.replicas }} replicas behind the ingress, and nothing pins a client to
one. ingress-nginx balances the pods itself and ignores the Service's affinity,
so a reconnecting client lands on any replica and refuses its host key. With
ingress-nginx, add to ingress.annotations:

    nginx.ingress.kubernetes.io/upstream-hash-by: "$remote_addr"

Another controller needs its own equivalent.
{{- end }}
{{- else }}

The ingress is disabled, so nothing outside the cluster can reach this yet.
For a look before you expose it:

    kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "remote-docker-workspace.fullname" . }} 2222:{{ .Values.service.sshPort }}
    remote-docker remote create dev --host 127.0.0.1 --port 2222 --user <account>
{{- end }}

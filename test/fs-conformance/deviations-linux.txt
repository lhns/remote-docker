# Where a share is allowed to differ from a native bind mount, on Linux.
#
# test/fs-conformance/diff.sh reads this file. Every line that is not blank
# and does not start with `#` is one SHARE-side transcript line, verbatim, as
# fsprobe printed it when run against a share:
#
#     <group>/<step>: <op> -> <result> [<stat>]
#
# A step whose share line differs from the native one is fine only if the
# share line is in here. The line directly ABOVE each entry is a comment that
# gives the reason and a pointer -- the ADR that decided it, or the README
# caveat that documents it -- in the form
#
#     # <reason> (<pointer>)
#     <share-side transcript line>
#
# An entry with no reason above it is warned about; an entry no run observes
# any more is STALE and fails, so this file cannot silently outlive the
# behaviour it excuses. Never hand-predict a line: diff.sh writes
# suggested-deviations.txt beside its report with the exact share lines it
# could not explain, and that file is what an entry is copied from.
#
# mode, uid and gid appear on the attrs group's lines and on create/create
# only (step.format in test/probes/fsprobe/stat.go), so the one ownership
# policy is compared once per run instead of on every stat line. The share
# synthesises 0666 for a file and adds 0111 where the real file is executable
# (nfsserve/attrs.go), which is why the modes below stop changing after
# attrs/chmod-x leaves the file executable.

# a share reports the workspace account as owner with wide bits (ADR 0046)
create/create: open(O_CREAT|O_EXCL) f -> ok [file ino#1 nlink=1 size=0 mode=0666 uid=10000 gid=10000 mtime=new]

# NFS silly-rename: the client renames a file unlinked while open, so the name
# still exists and nlink stays 1 where a native unlink drops it to 0
remove/unlink-open.write: write 100 bytes via fd, fstat -> ok:size=100 [file ino#1 nlink=1 size=100 mtime=new]

# NFS silly-rename: the client keeps a .nfs* name for a file unlinked while open
remove/unlink-open.readdir-open: readdir for .nfs* while open -> ok:sillyrename

# a share reports the workspace account as owner with wide bits (ADR 0046)
attrs/create: create m -> ok [file ino#1 nlink=1 size=1 mode=0666 uid=10000 gid=10000 mtime=new]

# a share reports the workspace account as owner with wide bits (ADR 0046)

# a share reports the workspace account as owner with wide bits (ADR 0046)

# a share reports the workspace account as owner with wide bits (ADR 0046); chown is accepted and dropped

# a share reports the workspace account as owner with wide bits (ADR 0046), so git's safe.directory check sees a foreign owner

# NFS silly-rename: a file unlinked while open keeps a .nfs* name, which the

# name at any point (README, "What differs from a bind mount")

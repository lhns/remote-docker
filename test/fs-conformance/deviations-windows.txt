# Filesystem conformance: where a share backed by an NTFS directory on a
# Windows client is allowed to differ from the native oracle.
#
# Read by test/fs-conformance/diff.sh, which fails the machine.yml job on any
# difference between transcript-native.txt and transcript-windows.txt that is
# not listed here. The Linux leg (test/fs-conformance.sh) has its own file.
#
# Format:
#   - a line starting with `#` is a comment
#   - each deviation is two lines: a `# reason (pointer)` comment naming why
#     the share is allowed to differ and where that is reasoned about (an ADR,
#     a test section, a kernel or NTFS reference), followed by the share-side
#     transcript line VERBATIM, as fsprobe printed it:
#       <group>/<step>: <op> -> <result> [<stat>]
#   - every other non-comment line is such a transcript line
#
# A deviation nobody can explain is a bug: it stays out of here and fails the
# job until somebody names it. What the Linux file lists and also happens here
# is repeated here; NTFS's own differences follow.
#
# mode, uid and gid appear on the attrs group's lines and on create/create
# only (step.format in test/probes/fsprobe/stat.go), so the one ownership
# policy is compared once per run instead of on every stat line.
